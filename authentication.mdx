Mais Linda authenticates every API request using an API key passed as a Bearer token. You generate keys from your dashboard and include them in the `Authorization` header of every request you make. Requests without a valid key are rejected before they reach any endpoint.

## Generating an API Key

API keys are created and managed from the Mais Linda dashboard. Each key is tied to your account and inherits the permissions of the role you assign it.

<Steps>
  <Step title="Open API Key Settings">
    Log in to [https://app.maislinda.com](https://app.maislinda.com) and click **Settings** in the left-hand navigation. Then select **API Keys** from the settings menu.
  </Step>
  <Step title="Generate a New Key">
    Click **Generate New Key**. Enter a descriptive label — for example, `production-backend` or `local-dev` — so you can identify the key's purpose later. Then click **Create**.
  </Step>
  <Step title="Copy and Store the Key">
    Your new API key is displayed once. Copy it now and store it in a secure location such as a secrets manager or a local `.env` file that is not committed to version control.

    <Warning>
      Your API key is shown only once. If you lose it, you cannot retrieve it — you will need to revoke the old key and generate a new one from your dashboard.
    </Warning>
  </Step>
</Steps>

## Making Authenticated Requests

Include your API key in the `Authorization` header of every request using the `Bearer` scheme:

```
Authorization: Bearer YOUR_API_KEY
```

The examples below show how to authenticate a request that lists your agents.

<CodeGroup>
  ```bash cURL
  curl https://api.maislinda.com/v1/agents \
    -H "Authorization: Bearer YOUR_API_KEY"
  ```

  ```javascript JavaScript
  const response = await fetch('https://api.maislinda.com/v1/agents', {
    headers: {
      'Authorization': 'Bearer YOUR_API_KEY',
      'Content-Type': 'application/json'
    }
  });
  ```
</CodeGroup>

Replace `YOUR_API_KEY` with your actual key. All API requests must be made over HTTPS — plain HTTP requests will be rejected.

## Authentication Errors

When a request fails due to an authentication problem, the API returns one of the following HTTP status codes:

| Status Code | Meaning |
|---|---|
| `401 Unauthorized` | The API key is missing, malformed, or has been revoked. Check that your `Authorization` header is present and correctly formatted. |
| `403 Forbidden` | The API key is valid, but it does not have permission to perform the requested action. Check the key's assigned role in your dashboard. |
| `429 Too Many Requests` | Your key has exceeded its rate limit. Wait before retrying, or contact support to discuss a higher limit. |

A `401` error response looks like this:

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Missing or invalid API key. Include your key as a Bearer token."
  }
}
```

If you receive a `401` unexpectedly, verify that:
- The `Authorization` header is spelled correctly and uses the `Bearer` prefix.
- The key has not been revoked from your dashboard.
- You are not passing the key as a query parameter instead of in the header.

## Security Best Practices

Protecting your API keys is critical to keeping your agents and account data secure.

<Tip>
  **Never expose your API key in client-side JavaScript or public repositories.** If your key appears in browser-accessible code or a public GitHub repo, rotate it immediately from your dashboard.
</Tip>

<Tip>
  **Use environment variables to store keys in your application.** Reference them at runtime (e.g. `process.env.MAISLINDA_API_KEY`) rather than hardcoding the value in source files.
</Tip>

<Tip>
  **Rotate keys periodically and immediately after any suspected compromise.** Regular rotation limits the window of exposure if a key is ever leaked. Revoke the old key before or immediately after issuing a replacement.
</Tip>

<Tip>
  **Use separate keys for development and production environments.** This limits the blast radius if a development key is accidentally exposed, and lets you revoke or throttle it without affecting live traffic.
</Tip>
